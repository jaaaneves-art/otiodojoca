# OTJ-QA-V02 — Testes Unitários

**Código:** OTJ-QA-V02  
**Projeto:** O Tio do Joca (OTJ)  
**Área:** Qualidade e Testes (QA)  
**Versão:** 1.0  
**Estado:** Em desenvolvimento

---

# Objetivo

Definir a estratégia de testes unitários do projeto O Tio do Joca (OTJ), assegurando que cada componente de software é validado individualmente antes da integração com o restante sistema.

---

# Conceito

Os testes unitários verificam o comportamento de pequenas unidades de código, como funções, métodos ou classes, de forma isolada.

O seu principal objetivo é detetar erros precocemente e aumentar a confiança nas alterações efetuadas ao código.

---

# Objetivos

- Validar funcionalidades individuais.
- Reduzir regressões.
- Facilitar a manutenção do código.
- Melhorar a qualidade do software.
- Apoiar a refatoração.

---

# Âmbito

Os testes unitários deverão abranger:

- Funções utilitárias.
- Serviços.
- Componentes de negócio.
- Validações.
- Transformação de dados.
- Lógica crítica da aplicação.

---

# Boas Práticas

- Um teste deve validar apenas um comportamento.
- Os testes devem ser rápidos e independentes.
- Evitar dependências externas.
- Utilizar dados previsíveis.
- Nomear os testes de forma clara.

---

# Automatização

Os testes unitários deverão ser executados automaticamente:

- Em ambiente local.
- Na pipeline de CI.
- Antes de cada release.

---

# Cobertura de Código

A cobertura de testes deverá ser monitorizada regularmente.

A prioridade deverá ser dada aos módulos críticos da aplicação, em vez de procurar apenas uma percentagem elevada de cobertura.

---

# Ferramentas

As ferramentas poderão variar conforme a tecnologia utilizada, devendo ser escolhidas de acordo com as necessidades do projeto.

---

# Critérios de Aprovação

Uma funcionalidade deverá ser considerada pronta quando:

- Todos os testes unitários forem aprovados.
- Não existirem falhas críticas.
- A cobertura dos componentes essenciais for considerada adequada.

---

# Conclusão

Os testes unitários constituem a primeira linha de defesa contra defeitos, contribuindo para uma base de código mais robusta, estável e fácil de evoluir.
