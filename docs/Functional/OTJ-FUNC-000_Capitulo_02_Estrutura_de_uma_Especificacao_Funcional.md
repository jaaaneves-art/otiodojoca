# OTJ-FUNC-000 --- Norma para Especificações Funcionais

# Capítulo 2 --- Estrutura de uma Especificação Funcional

## 2.1 Finalidade

Este capítulo define a estrutura obrigatória que deverá ser utilizada em
todas as Especificações Funcionais do Projeto O Tio do Joca, garantindo
uniformidade, consistência e facilidade de manutenção.

## 2.2 Estrutura Geral

Cada documento funcional deverá seguir, sempre que aplicável, a seguinte
organização:

1.  Identificação do Documento
2.  Objetivo
3.  Âmbito
4.  Glossário
5.  Utilizadores
6.  Perfis e Permissões
7.  Casos de Utilização
8.  Fluxos Funcionais
9.  Regras de Negócio
10. Modelo de Dados Envolvido
11. Interfaces
12. Integrações
13. Notificações
14. Auditoria
15. Critérios de Aceitação
16. Requisitos Não Funcionais
17. Evolução Prevista
18. Anexos

## 2.3 Identificação do Documento

Todos os documentos deverão incluir código, título, versão, data, autor,
estado, histórico de alterações e documentos relacionados.

## 2.4 Casos de Utilização

Cada funcionalidade deverá ser descrita através de Casos de Utilização
(Use Cases), contendo identificador, nome, objetivo, atores envolvidos,
pré-condições, fluxo principal, fluxos alternativos, pós-condições e
exceções.

## 2.5 Fluxos Funcionais

Sempre que adequado, deverão ser descritos o fluxo principal, fluxos
alternativos, fluxos de erro, estados possíveis e transições entre
estados.

## 2.6 Regras de Negócio

Cada regra deverá possuir identificador único, descrição, prioridade,
módulo aplicável e impacto esperado.

## 2.7 Critérios de Aceitação

Todas as funcionalidades deverão possuir critérios objetivos que
permitam validar o seu correto funcionamento durante os testes.

## 2.8 Consistência

Todas as Especificações Funcionais deverão utilizar a mesma
terminologia, numeração, modelo documental e organização estrutural.

## 2.9 Síntese

Uma estrutura uniforme facilita a leitura, implementação, manutenção e
evolução das Especificações Funcionais.
